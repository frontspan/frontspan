# Contributing

Frontspan is in Sprint 1. Please discuss changes in an issue before implementation. Accepted ADRs govern architecture; proposals are not commitments. Run the [contributor checks](README.md#contributor-checks) before opening an implementation pull request.

Use focused branches and pull requests targeting main. Include issue references, acceptance criteria, validation results and any unresolved risks. Authorized agents may merge verified documentation-only changes that do not introduce new architecture or security decisions, including records of previously approved decisions. New architecture decisions and security-critical changes require maintainer approval. Application code requires CI and review before merge; package publication requires maintainer approval. Branch protection and CI requirements are planned, not yet enforced.

Use synthetic API examples and avoid proprietary or personal information. Report security concerns privately to the maintainers rather than publishing exploitation details in issues. Dependency and copied-code licensing must be reviewed; follow the Apache-2.0 license and preserve required notices.

See [AGENTS.md](AGENTS.md) and [Sprint 1](docs/planning/SPRINT-01.md).
