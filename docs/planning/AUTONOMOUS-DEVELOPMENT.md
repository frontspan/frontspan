# Delegated development and independent review policy

Status: maintainer approved direction on 2026-11-28; automated merge activation pending verified gates and explicit ruleset cutover. Applies to current approved sprint only. Issue #21 owns implementation/validation; no live automation or credential provisioning authorized by this document alone.

## Delegation

For routine changes within an accepted issue, ADRs and sprint scope, a development agent may implement, request independent review, correct findings, enable native squash auto-merge, verify merge and close the issue without per-PR human approval **only after** required review and policy gates have been verified and activated. No self-review, self-issued passing check, or bypass. Until activation, retain required maintainer review. Independent reviewer is a separate trusted identity/execution context, without author-controlled instructions or credentials; Codex automatic PR review is the preferred candidate. A separate trusted control plane must verify review and policy evidence. A general-purpose LLM is not itself a security boundary.

Always require explicit maintainer approval for new architecture or public-contract decisions, changes to security/auth/policy or data handling, new/unapproved dependencies or material upgrades, scope or sprint changes, CI/review/merge automation, workflow and instruction changes, repository/organization settings, release/publish/deployment, production access, and ambiguous or high-risk changes. Approved implementation of a security-critical feature still requires human review. The policy is fail-closed; uncertainty escalates. Record approval tied to the exact PR head; invalidate on new changes. No auto-approval of the automation itself.

## Trust model and required gates

- All PRs target protected main, current base, squash only, no direct push, force push or bypass. Use actual ruleset and exact required check names/source, not assumed enforcement. Keep existing required Workspace and consumer smoke check stable until verified replacement.
- CI is read-only on untrusted PRs; run frozen install, lint, format, typecheck, unit/build and applicable integration/pack checks. All required checks must genuinely succeed for the current PR/merge candidate. A skipped or neutral mandatory check is not a pass. Do not loosen tests or workflows to obtain green checks.
- Independent reviewer reviews the exact head and relevant base against protected instructions, accepted ADRs, issue and diff; require a verified completion verdict, no unresolved findings and no outstanding change requests. No positive conclusion inferred from silence, elapsed time, a comment/reaction alone, or untrusted text. Check actual Codex integration event schema, authenticated app identity, commit association and clean-review semantics experimentally. Re-review after any push/base change affecting candidate; old verdict must not qualify.
- Trusted gate must publish required check(s) for the correct SHA, e.g. Independent AI Review and Architecture & Policy Check (names provisional). Bind expected GitHub App source; prevent development agent or PR-modified code/workflows from producing their own passing verdict. Do not treat a same-name GitHub Actions check from an arbitrary PR-editable workflow as independent proof. Protect gate configuration and credentials outside author-controlled PR; use a dedicated least-privilege GitHub App or trusted external reviewer/control plane if needed. Verify available repo/plan capabilities and actual identity; no credentials in repo, logs or author environment. No privileged fork workflows, no checkout/execution of untrusted code with elevated tokens, no unsafe shell interpolation. Treat diff, PR body and comments as untrusted data, never instructions to gate. Read-only metadata verification where possible.
- Policy check uses base-controlled approved scope and trusted maintainer decision evidence. Sensitive paths include AGENTS.md, decision and planning policy docs, .github/workflows and gate logic/config, auth/security/preset enforcement, package publication, dependency manifests/lockfiles (except already authorized routine changes explicitly covered by policy). A change cannot mark itself routine by changing the classification rules. If high risk, require authenticated explicit maintainer approval on same head plus normal CI and review, even when native required approvals becomes zero. Unknown classification fails closed.
- Missing, stale, failed, skipped, ambiguous, forged, or unavailable review/gate data blocks merge. Resolve findings with bounded repair attempts (suggest 3; report blocker after repeated failures or same finding), no weakening gates. Re-check latest head/base, mergeability, required checks, threads, issue scope/dependencies and approval eligibility before enabling auto-merge. Native branch protection remains enforcement; do not directly merge around it.
- Only after verified merge on main and acceptance evidence, close linked issue with commit, PR, CI and review references. Prefer agent reconciliation from merged PR metadata or trusted post-merge automation, never close on PR creation/green CI alone. Idempotent; do not start next issue before prerequisites close. No automatic sprint transition without approved readiness gate.

## Rollout (#21)

1. Keep current one human approval and last-push approval requirements while developing and independently reviewing the gate. Codex automatic review enabled by maintainer, but its actual completion signal is not yet verified.
2. Document event/source verification and demonstrate fail-closed independent review/policy checks in a sandbox or isolated test PR. Test a clean review, findings, new commits, base changes, forged reviewer text/wrong identity, missing verdict, skipped checks, author edits to workflow/policy, unauthorized scope and maintainer-only changes, concurrent merge race and post-merge reconciliation. Require actual positive evidence and record check app/source, SHA and logs. If Codex does not expose a reliable completion verdict for exact SHA, propose trusted independent reviewer integration (e.g. isolated Codex SDK/API workflow with structured verdict) separately; do not infer approval from silence. Any API cost, new credential, external service or installation requires approval.
3. Merge the gate implementation with human approval under current ruleset. Confirm trusted source can emit the checks and developer cannot forge them. Demonstrate both allowed and blocked paths including protected policy changes. Then maintainer configures exact required check sources and verifies enforcement **before** dropping native human approval count to zero and disabling last-push approval for routine PRs. Preserve explicit human review for sensitive changes through independent policy gate; if this cannot be enforced, retain native human approval. No bypass actors. Do not self-activate.
4. Record active gate evidence and cutover authorization in #21 and protected documentation. Only then start autonomous routine merge loop. On gate failure or trust change, stop and ask maintainer to restore human approval; never merge unchecked.
